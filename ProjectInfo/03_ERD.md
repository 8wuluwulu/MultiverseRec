| Решение                                              | Почему                                                                                                                   |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| **Одна таблица `content` вместо `books` и `movies`** | Проще писать гибридные запросы. Можно добавить сериалы, игры — не менять структуру.                                      |
| **`metadata` — JSONB, а не отдельные поля**          | У книг — автор/страницы, у фильмов — режиссер/год. JSONB позволяет хранить разное. Плюс можно искать внутри.             |
| **Отдельная таблица `embedding_cache`**              | Эмбеддинги генерируются долго. Если два пользователя ищут "Дюну", второй получит из кэша за 0.1 секунды вместо 2 секунд. |
| **`content_type` — VARCHAR с CHECK**                 | Ограничиваем только 'book' и 'movie', чтобы не было ошибок.                                                              |
| **Индекс IVFFlat на `embedding`**                    | Ускоряет векторный поиск в 10-100 раз.                                                                                   |
| **`ON DELETE CASCADE`**                              | При удалении пользователя удаляются его отзывы и поиски — не остается "сирот".                                           |
